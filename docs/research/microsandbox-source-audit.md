# microsandbox 0.7.8 源码审计

2026-10-09；固定 commit `7b7b9dc89e9a1c77801918f7833c3381d1754579`。本文件只描述独立源码审计及其接线含义，不把静态判断记为实测通过；实际运行结果见[可行性报告](./microsandbox-feasibility.md)。

## 影响实验配置的结论

- 使用独立 runtime home 和显式 local backend，预装 Linux Node/pnpm/Git/curl 的 image。Node SDK 已捆绑本平台 native addon、`msb`、`libkrunfw`，runtime discovery 不隐式下载；未缓存 OCI image 则另行获取。macOS 二进制不能在 Linux guest 中直接复用。[平台包](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/npm/darwin-arm64/package.json)、[setup](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/docs/sdk/setup.mdx)。
- Host bind 来源先由可信 adapter 确认权限并 canonicalize；尤其 `/tmp`、`/var` 在 macOS 含系统 symlink。默认 mount-root resolver 拒绝任何 symlink 组件，不能把这个启动错误当成目录沙箱不支持。上游 containment 测试同样 canonicalize 临时目录。[runtime 落实](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/runner/vm.rs#L2349)、[根路径测试](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/unix/tests/test_root_containment.rs#L27)。
- Explicit restricted network policy 必不可少：Rust `NetworkPolicy::default()` 是 Public profile，不能把默认配置当作 default deny。每种授权范围先使用独立 VM；不要把 SDK `modify` 的一般功能理解为 mount/network 热更新。[默认策略](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/model/policy/types.rs#L823)、[modify 字段](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/modify.ts#L47)。

## SDK 的 host 文件操作在 VM 安全边界之外

`copyFromHost(hostPath, guestPath)` 的真实 Rust 实现直接 `tokio::fs::File::open(host_path)`；`copyToHost` 在 caller 指定 host parent 中建立临时文件，收完数据后原子 persist 到 host destination。两者没有 Target Folders allowlist。它们是 host 可信控制面的文件传输能力，不能直接作为模型可任意调用的工具；adapter 必须核验 host 路径，或仅暴露 guest fs API 和固定挂载。[TS 透传](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/fs.ts#L161)、[真实读取](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/fs.rs#L1721)、[真实写入](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/fs.rs#L1773)。

Host copy 的 atomic rename、防中断覆盖、最终 symlink destination 拒绝是数据完整性措施，不等于范围授权；`copyFromHost` 的普通 File::open 会跟随来源 symlink，`copyToHost` 对 parent 也不是我们项目的安全目录能力。[发布流程](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/fs.rs#L1809)。同类 trusted API（创建挂载、选择 rootfs/image/home、host volumes 和 socket forwarding）也必须由 adapter 从已批准配置生成。

## 挂载与字面路径

Runtime 将 directory bind 建为独立 PassthroughFs，设置明确 `root_dir`、`readonly` 和默认 `no_symlink_root=true`；Node MountBuilder 没有暴露 `follow_root_symlinks` opt-out。Guest lookup 的名字验证拒绝空名、`..` 与 `/`，host inode lookup 不直接把任意 guest 全路径交给 host root。挂载内 absolute/relative symlink 在 guest 命名空间中解析；仍须实际验证 outside symlink、同父目录越界、host root 替换和硬链接，不能把上游单元测试当本机已验证。[构造](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/runner/vm.rs#L2349)、[Node opt-out 缺口](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/native/mount_builder.rs#L416)、[名字校验](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/shared/name_validation.rs#L16)。

这里没有 sandbox-runtime 的路径 glob 规则，但存在另一种限制：runtime wire grammar 为 `tag:host_path[:opts]`，parser 明确拒绝 host path 中的逗号，使用最后一个冒号分隔 options。空格、glob 字符和 Unicode 不应被当成 glob；冒号及逗号必须单独实测，不能笼统声称任意合法主机路径都支持。[真实 parser](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/runner/vm.rs#L3462)。

默认 strict stat virtualization 会检查 xattr 能力；RO 挂载只要求读取 xattr，RW 要求写入。系统/foreign-owned 文件夹可能需要选择 relaxed/off metadata virtualization，但 readonly、范围授权仍须保留。镜像内的 Linux 系统文件不暴露 host macOS 系统；文件 full access 需要可信 adapter 另行选择 host 广泛映射，不能把 guest `/` 等同 host `/`。整 host root 的 readonly/RW、SIP/TCC、符号链接和 guest UID 行为仍未实测。[metadata 规则](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/unix/mod.rs#L1042)。

## 网络、TLS 和 full access

Runtime network `strict` 默认 true。TCP proxy 会在 host 连接前使用 SNI 或 DNS cache 重新检查 domain policy；如果 hostname allow 只能覆盖不可检查的 TLS，strict 会拒绝。开启 TLS interception 可检查加密内的 HTTP authority；关闭 strict 则减少这层保证，不应记成同等强度配置。需实测原始 HTTPS、共享 CDN、SNI/Host 不一致、curl/Node/pnpm/Git 证书兼容，以及清除 proxy 环境变量后仍不能绕过。[默认配置](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/model/config/types.rs#L84)、[连接前规则](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/engine/tcp/proxy.rs#L196)、[opaque 判定](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/engine/tcp/proxy.rs#L598)、[TLS bypass 判定](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/engine/tls/proxy.rs#L219)。

`allow_all()` 将 ingress、egress 均设 Allow，无 rules；它包含私网/host，而默认 Public profile 不包括这些。应用 network full 如果只承诺域名外联，应显式限定方向/协议且不自动发布端口，而非直接暴露更广泛 SDK 策略。[真实定义](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/model/policy/types.rs#L295)、[地址分类](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/network/lib/engine/policy/destination.rs#L32)。

## 授权变化、执行与取消

TS `ModifyOptions` 只有 resources、env、labels、workdir、secrets 等与 apply policy；没有 mounts 或 outbound network policy 字段。公开 Sandbox TS 接口中未看到它们的修改方法。本轮应验证批准后新建另一 scope VM 与之后撤销的新 VM；不能断言 runtime 所有内部接口绝不支持热修改，也不能以原 VM config 对象已改证明实际授权已改。[接口](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/modify.ts#L47)、[Sandbox](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/sandbox.ts#L584)。

ExecOptions 原生提供 timeout、stdin null/pipe/bytes、tty；流式 handle 支持 signal、kill、resize。Deadline 不依赖持续轮询输出，wait 被取消也不会取消 deadline；要把用户 AbortSignal 主动接到 handle.kill，不能仅取消 host waiter。Guest ProcessManager 实际 signal 原 process group（负 PID），不是任意已脱离的新进程组。因此 per-command detached cancel 仍可能与 Codex 相同；整 VM kill 必须另测，不能混为一项通过。[选项](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/native/exec_options_builder.rs#L147)、[执行控制](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/exec.rs#L375)、[group 信号](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/agentd/lib/process.rs#L163)。

`stop()` 无限等待 graceful completion；`stopWithTimeout` 逾期报错但不 kill，甚至 zero timeout 不会发 shutdown。另有显式 kill/killWithTimeout，用于实验 cleanup 的有界强制回收；实际是否释放 guest detached、host runtime process、disk ownership 和 sockets 由探针确认。[stop 实现](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/stop.rs#L13)、[TS lifecycle](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/sandbox.ts#L614)。

Collected exec 将 stdout/stderr 持续追加到 Vec，stream 内部 event receiver 也为 unbounded。没有 Pi 那种自动截断和临时 output file；应用需自己 stream、有界展示及归档，有限大输出通过不能推断无限输出安全。[真实 collect](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/exec.rs#L415)。

## 模型 HTTP、并发与遥测

已读 local exec/fs 链通过 runtime/guest agent 的本地 relay/control transport，未要求模型 SDK 或强制模型代理，自己的模型循环可继续在主机。Explicit `setDefaultBackend("local")` 可避免 cloud profile 影响；`withDefaultBackend` 是 process-wide，不是 task-local，不能在并发工作中反复切换。每个 Sandbox 配置与 runtime 实例是应用应固定的授权单位。[backend API](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/src/runtime.ts#L30)、[local transport](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/client/ipc.rs#L34)。

源码中看到的 runtime metrics sampler 采集 guest/VM 指标并写入 host shared-memory slot，没有模型 HTTP；这只是已读路径的静态结论。NAPI/native runtime 外联不会全部经过 JS fetch/http hook，因此没有完整包捕获时不能声称整个依赖零隐式 HTTP。实验应分清 image/registry 下载、用户命令网络和模型请求，并记录观察方法。[指标实现](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/runner/metrics.rs#L99)。

## 定点诊断：host root 加 quota 的首次写入

实验协调者观察到 `bind("/").statVirtualization("off").quota(128)` 创建很快，而首次 guest fs.write 等待超过 80 秒、host runtime 持续消耗 CPU。源码给出一个先于 APFS/UID 猜测的可验证解释：`DirQuota::new` 不遍历挂载目录，`baseline()` 在首次 write/create 时才通过 `OnceLock::get_or_init` 同步执行 `subtree_size(root)`；`create` 与 write-intent `open` 都先调用 `quota_ensure_baseline`，之后才进行 host 文件 syscall。`subtree_size` 用 `read_dir` 栈逐个遍历所有目录，不跟随 symlink，但没有 device/inode 去重或 mount-boundary 限制。把 quota 放到 host `/` 会在首次写入扫描整个可读取目录树；增加 quota 数值仍不会避免这次扫描。该配置的长等待不能直接记为权限拒绝或 APFS 死循环。因果确认仍需要有界复现，本审计没有运行 VM。[lazy quota](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/quota.rs#L139)、[全树扫描](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/quota.rs#L238)、[create 前 baseline](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/unix/create_ops.rs#L67)、[open 前 baseline](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/unix/file_ops.rs#L58)。

继续追踪公开 SDK 的实际 spawn 后，**去掉 `.quota(...)` 也不会关闭扫描**：Bind 的 `None` 在 spawn 被 `unwrap_or(DEFAULT_BIND_QUOTA_MIB)` 换成默认 4096 MiB，再以 `Some(quota)` 写入 runtime mount 参数。`.quota(0)` 也不是关闭开关：Node 接受 uint32 零，runtime parser 转成 `Some(0 bytes)`，仍构造 DirQuota 和捕获 baseline，随后正数增长被拒绝。目前没有在已读公开 Bind builder/配置接口找到正式的 unlimited/disable 配额选项；不要把裸 runtime parser 在未传 quota 时得到 None 当作公开 SDK 具备该能力，也不要通过改内部启动参数伪造 SDK 可行性。待实测小目录 quota-zero/默认 bind 进一步确认；全 host root 写入的扫描成本是需如实报告的集成限制。[默认额度](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/sandbox/config.rs#L43)、[Bind spawn](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/rust/lib/runtime/spawn.rs#L3094)、[Node quota](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/sdk/node-ts/native/mount_builder.rs#L293)、[零值仍 Some](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/runtime/lib/runner/vm.rs#L3592)。

上述 Bind spawn 分支没有按 deployment profile 绕过 quota，所以切换 single-tenant/multi-tenant 不能消除此路径的默认 baseline。扫描只调用 `read_dir`、`file_type` 和 `metadata().len()`，读取目录名和文件元数据，不打开文件读取内容；`read_dir` 失败会跳过该目录，条目类型查询失败也跳过。它是同步扫描，没有独立超时；没有证据可以将高 CPU 的整个等待解释为无限循环，但 whole-root 的首次写入成本足以作为可复现的性能/兼容性缺口报告。[扫描 syscall](https://github.com/superradcompany/microsandbox/blob/7b7b9dc89e9a1c77801918f7833c3381d1754579/crates/filesystem/lib/backends/passthroughfs/quota.rs#L253)。
