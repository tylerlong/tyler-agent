# Agent 与调用的数据归属

## 决定

Chat 是持续对话容器；每次被接纳的用户 prompt 创建一个 Agent。统一使用 Agent，避免 Turn 与 Agent Run 表达同一件事。子任务扩展见 [ADR 0002](0002-sub-agent-ownership.md)。

Model Call 属于 Agent，Tool Call 属于发起它的 Model Call。通过关系派生任务归属、聚合回答、错误和活动时间，避免保存重复副本及维护同步逻辑。服务方的协议 ID 不替代本地实体身份。

Project 拥有目标文件夹，Chat 拥有当前模型与思考强度；执行时读取当前配置，Agent 不复制配置。Model Call 保存实际发送的请求，已经发出的请求不随配置变化而改变。

成功 Model Call 的脱敏完整响应是唯一输出依据，展示、复制、Agent／子任务结果及协议续接均从它派生。流式内容用于进行中展示；失败、取消或中断保留部分内容，成功后不合并最终响应省略的暂存内容。这样可以防止界面与模型后续输入使用不同的结果。

各层保存自己的状态与错误：成功的 Model Call 不因 Agent 达到执行上限而改为失败；Agent 不复制调用错误。工具返回实际结果，由远程模型决定继续或结束，本地不自动重试付费调用。

## 取舍

后续根任务的 Chat 上下文只包含此前成功任务的问题和回答；失败记录仍可查看。同一 Agent 的工具续接保留完整协议上下文，每次实际发送的输入保存在 Model Call 请求中，不另存历史快照。

采用单一当前数据库结构，不维护旧接口或数据库迁移分支。普通启动拒绝不支持的数据库，不自动删除或重建用户数据。

本机管理写入的保护边界由 [ADR 0004](0004-command-tool-isolation-boundary.md) 记录。
