# Structured file tools within Target Folders

Replace the example file counter with seven structured tools: `list_files`, `search_files`, `read_file`, `write_file`, `edit_file`, `move_path` and `delete_path`. Each Tool Call performs one operation with an independent result; repeated calls retain their identities and execute serially within the existing Agent loop, avoiding shell access and multi-path batch variants. The discovery/read trio is delivered in #125 and mutations in #126.

Project Target Folders, read anew before each call, are the only application-level filesystem authorization rule. Resolve containment for existing paths and destinations through existing parents; reject traversal, sibling-prefix tricks and symlink escapes, and do not recursively follow links outside scope. Hidden paths and `.git` are permitted within scope, with no Git requirement, clean/tracked checks, `.git` guards or Git recovery promise; OS permissions still apply. Mutation prerequisites are checked before changing files, errors and cancellation report actual effects without a rollback claim, and generic Tool Call history/redaction remain unchanged.

Reads/searches/edits/writes support UTF-8 text; listing/moving/deleting also support other files. Bound listing/search to 100 results with offset continuation and reading to 2,000 lines or 50 KiB with line/column continuation. Use relative-path Node `path.matchesGlob` discovery patterns and literal case-sensitive content queries; fixed bounds and one exact, uniquely matching edit keep the interface small without adding dependencies or configurable modes. File/folder moves reject destination collisions; writes create missing scoped parents, and directory deletion is recursive. Verification uses existing HTTP/model-loop fixtures, temporary folders/databases and fake models, checks actual filesystem effects/results and continuation, and retains the generic Chromium Tool Call coverage without paid requests or development database deletion in either file-tool slice.

Mutation results report paths and bytes written or deletion, without echoing whole content. Unsupported replacement text (NUL or unpaired surrogate) is rejected. Edits reject empty or ambiguous oldText, including overlapping occurrences. Move destinations require an existing parent and reject existing entries, including dangling symlinks. Cancellation or filesystem failure after mutation begins reports mutationMayHaveOccurred; operations are not transactional and have no rollback promise.
