# 项目指令的初始加载与按需读取

设计已确定，尚未实现。采用 [Codex 的指令发现约定](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，用 Node 标准库实现加载；现有 Codex 执行后端未提供可单独调用的 loader，引入完整 Agent 框架仅复用文件发现会扩大依赖和接线范围。任务判断遵循 [ADR 0005](0005-local-execution-and-model-decisions.md)。

每个 Root Agent 与 Sub-agent 开始时，本地从宿主用户目录的 `~/.weft/` 加载用户级指令，再为每个 Target Folder 加载最近 Git 仓库根到 Target 的祖先指令链；无 Git 仓库时只检查 Target。多个 Target 保持独立路径范围，共用来源只加载一次；每段内容标明来源和适用范围。模型同时遵守适用的祖先和局部规则，冲突时局部规则优先，用户当前明确要求优先。

每目录按文件是否存在选择 `AGENTS.override.md`，不存在时选择 `AGENTS.md`，两份不合并。选中空文件也不回退；读取失败如实报告，不改读另一份。第一版不自动加载其他产品的全局配置或备用名称。`CONTEXT.md`、README、CONTRIBUTING 和 ADR 是由项目指令或任务引导读取的参考文档。

初始自动加载共享 32 KiB UTF-8 文本预算，按用户级、Target 保存顺序及祖先到局部的顺序使用。达到上限时保留已读取内容，标明不完整内容及未加载来源，交给模型决定是否通过文件工具补读。成功内容与读取诊断进入实际 Model Call 输入，沿用现有请求记录，不另存指令历史副本。

本地只为 loader 读取上述具名来源提供窄范围只读能力；它不扩大普通文件和命令工具的权限。符号链接的实际目标超出约定指令范围时仍需额外授权；文档引用也不自动扩权。这是对 [ADR 0004](0004-command-tool-isolation-boundary.md) 通用读取规则的明确特例。

内置 prompt 要求模型在处理文件前检查并读取尚未加载的适用局部指令；模型通过现有工具发现更深目录的指令。初始与局部读取失败均告知模型，不自动终止整个 Agent。每个新 Agent 重新加载，运行中的 Agent 保留已加载内容；局部指令首次读取时使用当时内容，不设置文件监听或自动替换上下文。
