# 本地工具的执行与授权边界

## 后端选择

选择 Codex exec-server 的独立文件／进程协议，复用每次请求的权限策略、原生读取、patch 和受控进程生命周期，同时保留本项目的模型 HTTP 记录、Agent／子 Agent 与模型选择。它减少并发任务的权限接线，也避免引入另一个 Agent loop 或虚拟机环境。对比依据见 [Codex](../research/codex-exec-server-feasibility.md)、[Pi](../research/pi-sandbox-feasibility.md) 和 [OpenShell](../research/openshell-feasibility.md) 验证；实施规格见 [#145](https://github.com/tylerlong/tyler-agent/issues/145)。

优先沿用上游设计，仅为落实已确认的授权范围或解决实测开发命令失败调整配置，不复刻旧七文件工具接口。可信适配层构造明确的沙箱策略并绑定工具调用；模型不能提交原始 RPC 策略或使用其他任务的句柄。实验协议采用固定版本，独立运行配置并过滤继承环境，避免上游变化和凭据泄露。

## 权限与审批

文件和命令共用范围：Project 当前目标文件夹、所属 Agent 临时目录、项目授权及本次批准；必要系统与工具链路径只读。目录按字面路径授权，读写授权包含所需目录元数据，不默认开放共享临时目录或其他用户文件。

远程模型明确申请额外范围和理由；本地只校验、展示审批、落实授权并返回事实。执行中的权限错误不会自动触发审批、扩权或重试；下一步决策属于模型。

用户可拒绝、允许一次或始终允许当前 Project。一次批准绑定原 Tool Call 及其不可变操作；持久授权放在 Project Edit，供同项目现有／未来 Chat 与主／子 Agent 共用，以减少重复审批。只保留一个持久授权层级。

Chat 分别保存文件和网络的受限／完全访问模式；全局默认只初始化新 Chat，与模型选择一致，不增加动态继承或 Project 模式覆盖。文件完全访问仍受 OS 权限约束；网络完全访问采用原生完整网络能力，域名 wildcard 不能代替它，因为受管代理仍限制本机／私网。受限模式沿用上游网络保护，localhost 测试所需的本机网络能力可明确申请，不自行增加按端口隔离。

工具实际启动时读取当前权限，运行中保持获准快照；修改授权不意外中断已运行操作，需要立即停止时使用取消。授权或模式变化后重检待审批申请，仅保留未满足需求，已结束调用不重放。等待审批没有超时，执行预算从实际启动开始计算。

审批及管理写入需要每次启动的服务内存凭据，通过终端管理 URL 交给用户。Host／Origin 校验不能独自证明原生本机客户端的用户身份；凭据不交给命令环境或模型，不扩展为通用账号系统，也不承诺防御已获完全文件访问的恶意同账号进程。

## 输出与生命周期

实际命令输出归属 Tool Call 并持久保存，返回模型的结果有长度上限，可继续读取所属任务的输出。上游临时回放不能替代应用记录；失败、超时和取消仍保留已收到的输出与状态。使用工具日志查看，不引入终端模拟器。

取消等待受控执行清理后进入终态；服务退出、执行器丢失和重启保留中断事实，不恢复旧句柄或重放操作。工具结果报告真实效果，不承诺文件回滚。

临时目录以 `/tmp/tyler-agent/` 为父目录，按服务实例和 Agent 隔离，避免并行任务及不同数据库互相覆盖。应用不自行定期清理，交给系统回收，不保证保留或清理期限；长期成果应存入项目目录。

## 已知边界

首版面向单人 macOS 使用，隔离采用 best efforts。范围覆盖工具启动的受控进程及后代；独立启动的 watcher 属于用户运行环境。保留正常符号链接行为，实际目标须获授权；已有跨范围硬链接可能影响范围外同一 inode，故意脱离进程组的后台进程不保证全部回收。

交互 PTY、stdin、长期后台会话和项目 `AGENTS.md` 加载留待实际需求后支持。[ADR 0003](0003-structured-file-tools.md) 的旧工具接口及具体算法不作为兼容要求。
