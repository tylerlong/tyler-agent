# 面向模型的文本读取与完整行分页

`read_file` 按完整行分页读取文本，成功结果不重复携带 base64。本决定定义 Weft 自己的模型工具契约，底层继续复用 Codex exec-server 的文件 RPC，不把字节传输协议直接当作模型阅读接口。实现与验证结果见 [#184](https://github.com/tylerlong/tyler-agent/issues/184)。

采用的契约：

- 文本分页不拆分可读字符，以 Unicode 扩展字素簇作为不可拆分边界，包括组合重音和 emoji 序列。保留正文原文，不规范化 Unicode、不转换换行；分页不得引入乱码、遗漏或重复。文件开头的 BOM 按下面的编码标记约定处理。
- 对外按行请求、整行返回，参数明确使用 `start_line`、`max_lines`，不再把底层字节位置或字素计数直接作为模型分页参数，不为随机字符位置建立索引。
- 默认最多返回 2,000 行，文本输出保留现有 50 KiB 大小保护，先达到哪项就结束当前页；只返回完整行，不新增设置项。2,000 行参考 Pi 的既有约定，50 KiB 沿用当前 Weft 的实现量级；这是本轮明确采用的默认值。
- 输入 `path` 为绝对路径；`start_line` 为从 1 开始的正安全整数，默认 1；`max_lines` 为正安全整数，默认 2,000，可按请求调整，仍受 50 KiB 文本输出保护。
- 成功结果只返回 `path`、`text`、`encoding`、`next_line`；`encoding` 告知模型原文件编码，`next_line` 为下一次应读取的行号，真正到达文件末尾时为 `null`。不统计全文总行数，不重复返回 `eof`、字节偏移或 base64。
- LF、CRLF、独立 CR 都作为行结束，CRLF 算一次换行且保持完整；保留原始换行及末尾换行，没有结束换行符的最后一行正常返回，末尾换行不凭空增加一行。空文件成功返回空文字；非空文件的起始行越界明确报错。
- 单行超出输出预算时不截断、不跳过、不自动提高上限。如果本页已有可返回的完整行，先返回这些行，`next_line` 指向尚未返回的行；如果请求的第一行本身超出预算，明确报告超长行，交给模型选择现有命令提取内容。
- `read_file` 用于阅读文本，图片继续使用现有 `read_image`。一般二进制文件明确提示不能作为文本读取，由模型选择现有命令或 MCP 工具处理；本轮不增加原始 base64 读取模式或通用文件转换器。
- 成功的文本结果只含文字和必要分页信息，不返回重复 base64，也不另存隐藏的原始文件副本。内部无损字节读取及 `read_image` 使用的原图能力继续保留。
- 文件本身的编码不支持或内容损坏时明确报告读取失败，不用替换字符静默冒充正常内容；错误交给模型选择后续处理。正常文件被分页切断造成的解码问题必须由实现消除，不能归咎于文件损坏。
- 支持 UTF-8（包括带 BOM 的文件），以及带 BOM 的 UTF-16 LE／BE；不自动猜测其他编码，无明确支持时报告错误，由模型选择现有命令转码。优先使用运行时已有解码能力，二进制检测与严格解码校验分别承担职责。
- 保持实现简单，优先使用运行时内置能力或成熟第三方实现。若最小封装无法满足上述约定，先评估第三方方案，不自行建设复杂的字符分割、编码识别或文件读取子系统。
- 按需从文件开头扫描到请求的行，及时丢弃跳过的内容，只保留所需页；只保证实际读取并解码过的内容有效，不为本页验证预先扫描全文。每次读取当前文件，不建立索引、全文快照或跨调用缓存；靠后行号可能需要较长扫描，不保证跨次读取期间文件不变。
- 新接口只接受 `path`、`start_line`、`max_lines`；旧 `offset`、`limit`、未知字段和非法参数明确报错，不保留别名，不把旧字节参数静默解释为行。历史调用记录原样保留。

## 工程约定

用户要求普通工程细节按成熟实践自行确定，只有影响产品能力、明显增加复杂度或存在实质争议的取舍才继续询问。本节据此收敛，不再把大小计量、BOM 等细节拆成审批问题。

- 50 KiB 指返回 `text` 编码为 UTF-8 后最多 51,200 字节，包含原始换行，不包含 JSON 元数据；不按源文件的 UTF-16 字节数、JavaScript 字符串长度或估算 token 数计算。
- 文件开头识别到的 BOM 只用于确定编码，不进入正文；正文其他位置的 U+FEFF 原样保留。`encoding` 为 `utf-8`、`utf-8-bom`、`utf-16le` 或 `utf-16be`，后两项表示本轮支持的带 BOM 文件；仅有 BOM 的文件按空正文处理。
- 解码及跨读取块的编码状态使用运行时已有能力，严格报告实际解码过的损坏／不完整内容，并拒绝未支持的编码标记，不把其它 BOM 误认为受支持的 UTF-16。完整行输出满足字符完整性约束，不需要自己实现字素分割算法或索引。类型识别使用可接收 RPC 字节 Buffer 的成熟内容检测库 `isbinaryfile`，不自写二进制阈值规则或凭扩展名决定类型。启发式类型识别不替代严格解码，也不保证任意文件都能准确分类。
- 扫描只保留必要的块、换行衔接状态及本页文字；丢弃已跳过的内容，不为靠后行号累计全文。资源保护通过已有取消／RPC 生命周期和所选完整行的输出预算实现，不另建文件服务、会话、缓存、全文大小配置或后台索引。遇到实现复杂度超出这类小适配时，先评估成熟第三方方案。
- `next_line` 必须反映实际可续读的位置，不能仅因为达到行数预算就宣称 EOF；必要的有限前瞻不等于全文校验。工具失败如实交给模型，不自动换命令、转码、重试或判定整个 Agent 失败。正规化后的实际参数（含默认值）交给 Jev 审核，并执行同一请求；沿用现有 Tool Call、Jev 开关、普通 Model Call 计数／上限、取消和记录语义，不为底层每个字节块新增模型调用。

## 交付与验收

- 同步模型工具 schema／说明、服务校验、Jev 所见的真实参数、读取适配、使用文档和测试。删除旧字节分页专属契约、重复 base64 输出及失去使用者的代码／fixture／断言；不保留兼容别名、弃用分支或 skip。历史 Tool Result 原样可查，复用现有记录及展示，不增加数据库结构或重建数据库。
- 保留内部原始字节能力，尤其 `read_image` 复用的完整图片读取；不得为删除文本结果的 base64 连带删除图片所需的共享实现。共享测试保留有效回归，只改废弃契约。
- 复用现有生产服务本机 HTTP、临时文件／数据库、受控模型 HTTP 和原生命令测试接缝；模型请求全部 mock。验证 ASCII／中文／组合字符／emoji 跨底层读取块、UTF-8 与带 BOM UTF-16、严格解码失败、二进制及不支持编码、BOM 标记与空正文。
- 验证不同及混合换行、无末尾换行、空文件、越界／无效参数、完整行与 50 KiB 边界、超长首行及有效前页、真实 EOF／`next_line`、大段前缀跳过、取消后句柄关闭和 `read_image` 回归。对未变更文件连续续读，拼接页文本应还原解码后的正文（不含开头 BOM），无丢失、重复或换行改写；不承诺跨次修改文件时得到同一快照。
- 实施时完成适用的格式、类型、后端和原生测试，核对文档与残留引用，并如实区分受控协议验证与实际平台覆盖。具体通过项与平台覆盖以交付票中的验证记录为准。

本决定不改变命令日志分页，不增加数据库 schema／迁移／重建；验证使用临时数据与受控模型 HTTP，不操作真实数据库或调用付费模型。

参考：[Unicode 字素边界](https://www.unicode.org/reports/tr29/#Grapheme_Cluster_Boundaries)、[Pi 文本与图片读取](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/read.ts)、[OpenCode 文件读取](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool/read-filesystem.ts)、[Gemini CLI 文件内容处理](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/utils/fileUtils.ts)。这些实现主要采用行分页，其具体截断行为不等于本决定要求的字符完整性保证。
