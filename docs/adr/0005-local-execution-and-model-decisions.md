# 本地执行、模型决策与工作指令

Weft 扩展能力时采用三条职责规则，以保留模型按任务决策的能力，并让本地执行约束可靠、结果可追查：

1. 本地负责执行与保证：工具执行、权限、取消、预算和真实记录由代码保证。
2. 模型负责判断与选择：需要理解任务、判断相关性或决定下一步的事情交给模型。
3. Prompt 负责说明要求：模型应遵守的工作方法明确写入 prompt，本地不复制同一套语义判断。

默认通过工具完整开放能力，让模型根据实际 prompt 决定如何组合、何时使用及如何处理结果，包括尚未预料到的任务细节。模型能够依靠现有工具作出的选择，就由模型作出；工具不足时优先补齐通用能力，而不是增加针对某种任务的本地策略。

设计讨论只确认工具无法自行解决的产品边界与取舍；上游已有的接口约定和模型可在执行时决定的细节，直接复用或交给模型，不逐项要求用户预先设计。

项目指令采用[初始自动加载与模型按需读取](0006-project-instruction-loading.md)。模型的工作要求随输入提供，不依靠本地解析任意 shell 命令来推断全部工作范围。

已接入的 [Jev 安全审核](0004-command-tool-isolation-boundary.md) 已替代此前的固定命令护栏计划：关闭时不进行操作风险审核，开启时安全判断全部交给最新 Jev 模型。Jev 只判断工具操作是否危险，不评价任务合理性或相关性；Prompt 提供宽泛防误操作目标和实际操作，不附带聊天历史或复制严格路径／命令规则，不新增人工权限审批或本地风险黑名单；旧权限产品与执行环境清理由 #180 完成。模型风险判断不构成本地隔离保证。本地继续负责执行、取消、预算和真实记录，不依据审核结果判定整个任务是否成功。本地测试只 mock 模型通信，不调用付费模型。Jev 调用也是 Model Call，同样计入所属 Agent 的模型调用次数上限，复用现有记录与展示；没有具体特殊理由，不特殊处理。

资料读取或工具执行失败均如实告知模型，由模型按任务选择补读、询问用户或停止；此类失败本身不自动使整个 Agent 失败。权限、取消、预算及执行记录的约束仍由本地保证。工作指令的理解与遵守依赖模型，不构成本地强制执行保证。
