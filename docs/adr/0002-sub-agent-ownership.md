# 子 Agent 的创建来源与任务树

## 决定

根 Agent 与子 Agent 使用同一种实体和执行核心，避免引入第二套模型通信和任务生命周期。根任务属于 Chat；子任务唯一引用创建它的 Tool Call，沿 Tool Call → Model Call → Agent 派生父任务、Chat 和 Project。子任务的 prompt 与背景来自创建参数，不重复保存祖先关系或任务树。

子任务只接收显式 prompt 与背景，不自动继承父级历史，以保持上下文来源和 token 成本可知。模型与思考强度默认继承父任务的有效选择，也允许显式覆盖，支持不同模型并发协作。远程模型填写参数，本地校验已配置模型及其能力，不解释自然语言来选择模型。

创建工具立即返回子任务身份；终态结果主动交给直接父模型，不增加等待或轮询工具。流式进度供用户查看，不逐次触发父模型请求，避免不必要的调用。每个 Agent 的模型与工具序列保持串行，不同 Agent 可以并发；通知在下一次可发送请求中提供，并计入正常调用上限。

父任务在后代全部结束前不能进入终态，以保留对子任务的生命周期责任。父模型暂时结束响应但子任务仍在运行时，等待终态通知后继续；子任务失败不自动使父任务或兄弟任务失败。

用户可取消任意任务子树，父模型只可取消直接子任务及其后代。取消主动中断执行，清理完成后返回真实状态与已有输出；不把等待自然结束当作取消，也不撤销已经发生的文件修改。

## 取舍

子任务终态及工具结果如实交给模型，包括失败、取消和部分输出。本地不判断结果价值，也不替模型选择重试、汇总或取消其他任务。失败或用户取消不会自动重启原 Agent 或重试付费调用；模型重新委派会创建新任务并保留旧记录。

Chat 历史和最近活动仅由用户提交的根任务产生，子任务不冒充用户 prompt。用户可查看子任务详情，但不向其追加 prompt。

执行上限由 Settings 管理。子任务总量按根任务全树累计，完成或失败不退还数量，以约束成本；父任务自身循环停止后仍须等待已有后代清理。终态结果来自 Model Call 的权威响应，未成功任务保留实际部分结果，界面裁剪不改变交给模型的数据。
