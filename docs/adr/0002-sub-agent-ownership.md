# 子 Agent 的创建来源与生命周期

根任务与子任务共用实体和执行核心，避免第二套模型通信与生命周期。子任务引用创建它的 Tool Call，沿调用关系派生父任务、Chat、Project 和创建参数，不另存祖先关系或任务树。

子任务只接收显式 prompt 与背景，以保持上下文来源及 token 成本可知。模型和思考强度默认继承父任务的有效选择，允许显式覆盖；远程模型选择，本地校验模型及能力。

创建立即返回任务身份，终态结果主动交给直接父模型，减少轮询调用。流式进度供用户查看，不逐次唤醒父模型。单 Agent 的调用串行，不同 Agent 可并发。

父任务负责等待全部后代结束；模型暂时交还控制后可等待子任务通知继续。子任务失败不自动使父任务或兄弟失败。全树累计创建上限不因任务结束而退还，以约束成本。

用户可取消任意任务子树，父模型只可取消直接子任务及其后代；主动中断并等待清理后返回真实状态和已有输出，不撤销文件修改。

如实提供成功、失败、取消及部分结果，由模型决定后续行动。重新委派创建新任务并保留旧记录；子任务不冒充 Chat 的用户提交，也不接受用户追加 prompt。
