# 子 Agent 的创建来源与任务树

本文记录已交付的子 Agent 契约及本次澄清。正常工具结果统一交回远程模型，不由本地判断结果价值。子任务进入成功、失败或取消终态后，默认通过事件通知父模型；不提供等待工具。取消工具先主动中断执行，再等待彻底停止后返回已有结果。

所有远程模型发起的 Tool Call 采用同一契约：不论执行结果如何，正常工具循环均如实提供返回内容与实际错误，不按成功、失败或取消筛掉结果。UI 可以采用不同的状态、样式或折叠方式展示，但不改写或过滤交回模型的数据，也不参与决定后续执行流程。

根 Agent 与子 Agent 使用同一种实体和执行核心，不创建额外 Chat 或 Sub-agent 表。根 Agent 直接属于 Chat；子 Agent 唯一引用创建它的 Tool Call，父 Agent、根 Chat 和 Project 沿 Tool Call → Model Call → Agent 关系派生，以保留精确的创建来源并避免重复保存祖先关系；此决定取代 ADR 0001 中暂缓子任务及所有 Agent 直接保存 Chat、prompt 的范围约束。

| 数据 | 唯一归属 |
| --- | --- |
| 根 Agent 所属 Chat | 根 Agent 的 chat_id |
| 子 Agent 创建来源 | 子 Agent 的 created_by_tool_call_id；每次创建 Tool Call 最多对应一个子 Agent |
| 子 Agent 的 parent、Chat、Project | 沿创建来源派生，不重复保存 ID |
| 根 Agent 的 prompt | 根 Agent |
| 子 Agent 的 prompt、context | 创建 Tool Call 的 arguments，不在子 Agent 中重复保存 |
| 执行状态及任务自身错误 | 各 Agent 自己 |
| 可读输出、模型调用错误及实际发送的完整输入 | 所属 Model Call，保留现有归属 |

Agent 行的 chat_id 与 created_by_tool_call_id 恰好一个非空；根任务保存 prompt，子任务的 prompt 与 context 从创建参数读取。创建关系不允许向既有 Agent 补挂父节点；每次创建新的子 Agent，形成可递归的任务树。接口可以返回派生的归属、prompt、context、回答和错误，读取结果不成为额外数据库副本。

子任务相关工具只有 create_sub_agent 与 cancel_sub_agent，不提供 wait_for_sub_agents 或轮询工具。create_sub_agent 在保存前，从当前根 Chat 选择、祖先覆盖及本次创建参数合成并校验最终有效配置；无效参数或配置不创建子任务、不占名额、不发子任务模型请求，有效显式子模型不被失效根选择提前拒绝。通过校验后保存并启动子任务，立即返回 agent_id 和初始状态，不等待它完成。当前模型响应的全部 Tool Calls 按序执行并配齐 function_call_output 后，父循环立即发出下一次请求，不等子任务完成；同一响应的多个创建结果一起交给下一次请求。创建 Tool Call 成功只表示子任务已创建，区别于子 Agent 执行成功；每个 Agent 保持自己的 Model Calls、Tool Calls 和状态，复用现有模型循环及调用记录。递归创建已纳入范围，具体上限归属 Settings。

子 Agent 进入 succeeded、failed 或 cancelled 终态后，如实将状态及已有输出提供给直接父模型，不等待其他子任务全部结束，也不要求父模型先调用等待工具；通知默认唤醒父 Agent 的执行循环。执行中的流式文字、Model Call 和内部 Tool Call 进度只用于实时查看，不逐次通知父模型；这是固定的通知契约，不由本地解释 prompt 判断更新价值。通知触发的模型请求计入该父 Agent 已配置的 Model Call 上限。

子 Agent 只接收创建参数中的 prompt 与显式文本 context，不自动继承父级对话历史；context 默认空字符串，blind 不增加独立开关或另一种 Agent 类型。模型与思考强度默认继承父 Agent 的有效配置，create_sub_agent 可通过 model_id 和 reasoning_effort 显式覆盖；覆盖值属于创建 Tool Call 的参数，不复制到 Agent 或 Chat。配置从根 Chat 当前选择开始，沿祖先创建参数逐级合成；每次 Model Call 先解析自己的有效选择，再校验实际模型及能力，实际请求保留当次使用值。没有覆盖的孙任务继承父任务的有效选择；文件访问沿 Project 读取当前范围，不建立配置快照或强制使用 worktree。

只覆盖模型时，新模型支持继承的思考强度则保留，否则使用新模型的默认强度；显式指定不受新模型支持的强度则返回参数错误，不发起付费 Model Call。reasoning_effort 显式为 null 表示使用所选模型的默认强度，区别于省略该参数时继承父级选择。

实现显式模型覆盖时，复用 Settings 中已有的模型 ID、名称和支持强度信息，在现有模型请求的工具说明中提供可选配置。远程模型根据 prompt 填写创建参数，本地只解析和校验参数，不解析用户自然语言来选择模型，不新增模型发现工具或额外模型调用。

Chat 的用户提交历史、后续用户任务的对话上下文和最近活动只由根 Agent 产生；子任务不冒充用户提交。UI 从同一关系派生可折叠任务树，点击节点复用 Agent 详情渲染并显示 prompt、context、调用及实时输出；子任务查看页没有追加 prompt 的输入框。实时事件沿用 Agent 更新通知，子任务树及详情缓存与用户 Chat 历史分离，刷新后从持久化创建关系恢复导航；不另存树结构或重复回答。

父 Agent 在所有直接子 Agent 进入终态之前，不能进入 succeeded、failed 或 cancelled；这条规则递归成立，因此根 Agent 的终态意味着整棵树已结束。自身模型循环停止后仍需等待未结束的子任务，自身调用失败不提前释放子任务责任；根 Chat 的 busy 锁持续到根 Agent 进入终态。生命周期的收尾约束不延迟向父模型提供子任务状态通知。

父模型返回没有 Tool Call 的文本，但仍有未结束子任务时，父 Agent 保持进行中，暂时不发起新的模型请求；下一条子任务终态通知到达后继续模型循环。所有子任务结束、已有终态通知已交给父模型处理，且父模型不再请求工具时，父 Agent 才可成功结束。create_sub_agent 的即时创建结果与后续子任务终态通知是不同的信息；本地不根据子任务成败自行改写父模型答复，下一步任务决策属于远程模型。

已确认的工具说明补充（待实现）：创建后立即返回子 Agent 编号和初始状态；子任务成功、失败或取消后，运行服务在后续模型请求中提供状态和结果。模型可以继续处理独立工作；需要等待时，结束当前响应且本轮不发起 Tool Call，运行服务等待子任务结果后继续请求。这只是说明已有控制交还与通知机制，不增加等待／轮询工具或固定任务策略。

远程模型请求是无状态的；每次 HTTPS 请求携带必要本地历史、此前完整协议输出、配对工具结果与当时已排队的生命周期事实，不依赖服务方保存的 ID 或前次请求。不同 Agent 可以同时执行，每个 Agent 的模型请求及工具序列保持串行。空闲时收到终态通知即可继续请求；通知若发生于正在执行的模型请求或工具期间，按发生顺序暂存，在下一个可发送请求中提供当时已有的通知，不等其他任务、也不增加定时聚合。使用运行期间的通知数组与唤醒 Promise，不新增通知数据库表；实际发送的通知属于当次 Model Call 输入记录。停止请求、模型调用失败或调用上限已经终止父循环时，不因后续通知重启循环或越过上限，已有结果仍持久化并可查看。

终态通知使用带任务 ID 和运行服务来源标记的普通模型输入消息，不伪造 Tool Call 或复用已经返回的创建 call ID；它不成为新的用户 prompt、Agent 或 Chat 历史项。[Responses 的普通输入消息示例](https://github.com/OpenRouterTeam/docs/blob/main/api_reference/responses/reasoning.mdx)支持这一传输方式。

用户可以请求取消任意 Agent 及其全部后代，包括根 Agent；父 Agent 通过 cancel_sub_agent({agent_id}) 只能取消自己直接创建的子 Agent 及其全部后代。取消一个子任务不自动取消父任务或兄弟任务，取消根任务则停止整棵树。取消后停止发起新工作，中断正在运行的请求或工具，等待清理和后代结束后进入独立的 cancelled 终态；保留已有输出与调用记录。用户取消子任务属于执行控制，不开放追加 prompt。

cancel_sub_agent 的行为是主动停止：阻止目标及其后代继续发起模型调用、工具和子任务，中断当前 HTTP 请求及受控工具执行，然后等待这些工作与清理结束。工具直到目标彻底停止后才返回真实终态、已有输出及错误；不提前返回仅表示已接受取消的确认，也不把继续自然运行到结束当作取消。目标已进入终态时保持其原状态，如实返回。用户停止操作复用相同取消核心，UI 可以立即显示正在停止，但不能提前标记 cancelled。

用户取消的对象是指定 Agent 及其后代，父模型随后如何处理取消结果沿用普通工具规则；本地不通过比较 prompt 禁止模型重新委派任务，也不自行重新启动被取消的 Agent。希望结束整个任务时取消根 Agent。

子任务状态通知如实提供任务状态、已有可读输出及错误或取消信息，不因失败或取消而隐藏已有输出；准确的执行状态区分完整成功结果与未成功任务的部分输出。子任务失败或取消不自动使父 Agent 失败。本地不解释 prompt、不判断输出是否有用，也不替模型选择继续、重试、汇总或取消其他任务。父模型依据 prompt 和如实返回的结果决定下一步；重新尝试通过 create_sub_agent 创建一个新的单次任务，保留原 Agent，不重置其状态或记录，也不自动重试已失败的付费 Model Call。

取消工具返回的终态与已有结果本身可完成该次子任务结果的投递，不为相同终态另外唤醒一次父模型；普通完成或用户取消子任务时，通过默认终态通知投递。工具结果仍按协议完整回传，UI 更新照常独立发布。成功结果从所属 Model Calls 的权威完整响应派生；失败或取消结果保留可用的部分快照、Tool Results 及实际错误，不使用界面折叠或显示裁剪后的内容作为模型输入。

Settings 持久化两个用户可配置的正整数执行上限，默认值不在 Agent 中另存副本：

| 设置 | 默认值 | 计数范围 |
| --- | --- | --- |
| 每个 Agent 的 Model Call 上限 | 16 | 该 Agent 自己已经发起的 Model Calls，包括失败调用 |
| 每个根任务的子 Agent 总量上限 | 32 | 全树累计创建的后代，包含嵌套、已完成、失败及取消任务，不包含根 Agent |

子任务结束或失败不退还累计创建数量；参数验证失败且未创建 Agent 时不占名额。每次新 Model Call 或子任务创建前读取当前 Settings，修改上限不撤销已发出的调用或已创建的子任务；降低到已用数量以下时阻止继续调用或创建。沿用现有最后一次 Model Call 的工具执行边界：若该调用仍请求工具，将其记录为未执行并以 modelCallLimit 停止自身模型循环；已启动的子任务仍须等完后才能将父 Agent 标为失败。不增加全局并发队列或父任务占用的调度槽。
